# デフォルメ・スポーツゲームUI全面刷新 設計仕様

実施日: 2026-07-29

## 1. 目的

既存のFootball Directorを、承認済みの参考画像と同じ方向性を持つスマートフォン最適化サッカー管理ゲームUIへ刷新する。

- 深いネイビーと鮮やかなブルーを基調にしたソーシャルゲーム型HUD
- 3〜4頭身のオリジナルデフォルメキャラクター
- 選手カードを直接ピッチに配置する編成体験
- ホーム、編成、試合、移籍、クラブで一貫した画面世界観
- 既存のゲームロジック、セーブデータ、クラウド保存仕様は維持

## 2. デザイン基準

承認済み画像 `サッカー管理ゲームの魅力的な広告.png` を唯一のビジュアル基準とする。実在ゲームの画面やキャラクターは複製せず、配色、情報密度、キャラクター比率、カード構造、画面遷移の考え方のみを参考にしたオリジナル実装とする。

### 2.1 色

- 背景: `#061126`〜`#0B1F45`
- 主要パネル: `#102D5B`〜`#17457C`
- 選択・主要操作: エレクトリックブルー
- 好調・完了: ライムグリーン
- 高レア・報酬: ゴールド
- 警告: オレンジ
- 危険・負傷: レッド

全面発光は避け、主要CTA、選択中ナビ、新着、高レアカードだけを強く発光させる。

### 2.2 キャラクター

- 全キャラクターを3〜4頭身に統一
- 大きな目と分かりやすい表情を持つスポーツアニメ調
- 選手、戦術アシスタント、スカウト、監督、マスコットを同じ画風で統一
- 参考画像の黒髪女性アシスタント、青ユニフォームの主力選手、緑ユニフォームのGK、探偵風スカウト、スーツ姿の監督、犬マスコットを正式な基本キャストとする
- 画像は透明背景WebPを使用し、カード・イベント・ヒーロー領域で再利用する
- 簡易SVGを正式キャラとして使用しない

## 3. 画面構造

### 3.1 共通ナビゲーション

スマートフォン下部ナビは5項目固定とする。

1. ホーム
2. チーム
3. 試合
4. 移籍
5. クラブ

各ボタンは44px以上、safe-areaを考慮し、横スクロールを発生させない。

PCでは既存の6カテゴリを維持し、同じデザイントークンとキャラクターアセットを使用する。

### 3.2 ホーム

- クラブレベル、コイン、補助通貨を上部HUDに表示
- 次戦カードを画面上部の主役とする
- 戦術アシスタントを次戦カード内に大きく表示
- チーム総合力と士気を大きな数値で表示
- ミッション、プレゼント、ショップ、スカウト、強化、練習へのゲーム型ショートカット
- 期間イベントのバナー
- 未処理判断を監督ミッションとして表示

### 3.3 チーム編成

- チーム総合力、チームスキル、攻撃、守備、技術、体力を上部表示
- ピッチ面積を最大化
- 選手は顔付きカードとして表示
- ポジション、レベル、総合値、役割バッジをカード内表示
- 控え選手を横スクロールカード列で表示
- フォーメーション、自動編成、役割設定、スキル管理、選手一覧を下部操作として表示
- 既存のドラッグ配置、固定起用、キャプテン、PK、交代方針を維持

### 3.4 試合

- スコア、時間、チームエンブレムを最上部固定
- 2Dピッチにデフォルメ選手を表示
- 左側またはボトムシートに試合統計と選手交代
- 右側またはボトムシートに戦術指示
- 速度変更、一時停止、攻撃的・守備的変更を1タップで操作
- 重要イベントはキャラクターカットインと短い演出を表示
- 既存の区間進行型試合計算は変更しない

### 3.5 移籍

- スカウト、特別スカウト、交渉中のタブ
- 注目選手を顔付きカードリストで表示
- レア度、ポジション、総合値、特徴、価格を一画面で確認可能
- 探偵風スカウトキャラクターをバナーとレポートで使用
- 既存の地域視察、候補リスト、クラブ交渉、代理人交渉、レンタルを維持

### 3.6 クラブ

- 資金、観客、評判、理事会評価をゲームHUD化
- 施設をアイコン付きカードとして表示
- スタッフ、理事会、サポーター、記録、キャリアへカード導線を設ける
- 監督とマスコットをクラブ画面の案内キャラクターとして使用

### 3.7 その他画面

以下も同じトークン、カード、ボタン、キャラ表示へ統一する。

- 新規ゲーム
- 日程・順位表
- 戦術・トレーニング
- アカデミー
- 記録・タイトル
- 秘書レポート
- 受信トレイ
- 選手詳細
- クラウド保存・読込
- 確認モーダル

## 4. レスポンシブ要件

- 基準: 390×844
- 必須検証: 320×568、360×800、390×844、430×932、768×1024、1366×768、1536×864
- 文書全体の横スクロール禁止
- 主要操作44×44px以上
- 固定ナビとモーダルの重なり禁止
- 選手カード同士の衝突禁止
- 文字を画像内へ焼き込まずHTMLで表示

## 5. アセット構成

`public/assets/game-ui/characters/`

- `assistant-normal.webp`
- `assistant-warning.webp`
- `assistant-win.webp`
- `player-star.webp`
- `player-gk.webp`
- `scout.webp`
- `manager.webp`
- `mascot.webp`
- `player-card-sheet.webp`

アセットはすべてオリジナルで、透明背景、同一画風、同一ライティングに統一する。

## 6. 実装方針

- 既存のHTML生成とイベントハンドラ構造を維持
- `src/ui/game-theme.js`でキャラクターとレアリティ表現を集中管理
- `src/ui/game-components.js`でHUD、キャラ、選手カード、ゲームボタンを共通化
- `src/ui/render.js`は画面固有のデータ組み立てに集中
- `src/styles.css`へトークンとレイアウトを追加し、既存CSSとの競合を限定
- データモデル、試合計算、保存スキーマは変更しない

## 7. テスト

- Nodeテストで全カテゴリと主要CTAのDOM契約を確認
- Playwrightで7ビューポートを検証
- ホーム、編成、ライブ試合、移籍、クラブ、新規ゲーム、モーダルを撮影
- 横はみ出し、カード衝突、タップ領域、JavaScript例外を自動検出
- ゲームロジックの既存回帰テストを全件維持

## 8. 完了条件

- 承認済み参考画像と同じ世界観が全主要画面で一貫している
- 正式キャラクター画像がホーム、編成、試合、移籍、クラブで使用されている
- 320px幅で操作不能・横はみ出し・カード衝突がない
- 既存テスト、品質検査、HTTPスモーク、production buildが成功
- Playwright全ビューポートが成功
- コードレビューで重大・高優先度の未修正事項がない
