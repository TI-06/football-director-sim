# 第3～5弾統合アップデート設計

実施日: 2026-07-27
対象: クラブライフ、監督キャリア、スカウト・移籍交渉、試合文化、PC・スマホ共通ゲームUI

## 目的

Football Directorを、試合と移籍だけでなく、スタッフ、人間関係、理事会、監督キャリア、スカウト、代理人、セットプレー、天候、ライバル関係まで一つの週間ゲームループで管理する長期運営シミュレーションへ拡張する。

同時に、機能追加による画面増加を抑え、PCでは左サイドバー・中央ワークスペース・右状況パネル、スマホでは主要5操作・ボトムシート・状況カードを使う共通情報設計へ再編する。

## スコープ

このアップデートは以下の3群を一つのリリースとして扱う。

1. 第3弾: クラブライフと監督キャリア
2. 第4弾: スカウト、移籍交渉、代理人
3. 第5弾: セットプレー、天候、ピッチ、遠征、ライバル、審判

旧セーブ互換は対象外とし、新規キャリア開始を前提とする。

## 非対象

- 実在クラブ、実在人物、実在大会名
- オンライン対戦、ログイン、クラウドセーブ
- 代表チーム、国際大会
- 決済、課金アイテム
- 連続物理演算型の3D試合
- 完全自由形式の会話AI

## 共通設計原則

- 新しい機能を新規トップレベルタブとして増やさない。
- 毎週の「要対応」「準備」「試合」「結果」「経営判断」へ統合する。
- 重要案件はホームと右状況パネルへ最大5件まで表示する。
- ゲームルールはDOMから分離し、同じシードと同じ入力で再現可能にする。
- AIクラブも可能な範囲で同じ契約、スタッフ、スカウト、評価ルールを利用する。
- ブラウザ標準ダイアログは使用せず、既存のゲーム内モーダルとトーストを拡張する。

# 1. 情報設計とゲームシェル

## PC

3カラム型を標準とする。

### 左サイドバー

常時表示するトップカテゴリは6件に固定する。

- ホーム
- 試合
- チーム
- 移籍
- クラブ
- キャリア

カテゴリ内の詳細は、中央画面上部のコンテキストナビまたはカードから開く。

### 中央ワークスペース

現在の作業を表示する主領域。複数の大きな表を同時表示せず、上部に要約、下部に詳細を配置する。

### 右状況パネル

常に以下を表示する。

- 次戦
- 今週の要対応
- 秘書・スタッフ提案
- 選手の不満、負傷、契約期限
- 理事会・サポーター評価

試合中はスコア、戦術、交代、カード、体力へ自動的に切り替える。

### PC操作

- サイドバーは折り畳み可能
- 主要画面はURLハッシュまたは内部ルートで復元可能
- キーボードショートカットを追加
  - H: ホーム
  - M: 試合
  - S: チーム
  - T: 移籍
  - C: クラブ
  - R: キャリア
- 右状況パネルのカードから直接対応モーダルを開く

## スマホ

下部5操作を維持する。

- ホーム
- 試合
- チーム
- 移籍
- メニュー

クラブ、キャリア、スタッフ、記録、設定はメニューのボトムシートに集約する。ホームには固定の「次へ」操作と、最大5件の要対応カードを表示する。

## 共通画面ルール

- 一画面一目的
- 重要操作は常に最初のスクロール範囲に置く
- 一覧はフィルター保存と簡易検索に対応
- 右パネルとホームカードから同じ操作へ到達可能
- モーダルはEsc、背景クリック、フォーカストラップ、復帰フォーカスに対応

# 2. 第3弾: クラブライフと監督キャリア

## 2.1 監督プロフィール

監督状態に以下を追加する。

- 名前
- 年齢
- 出身地
- 得意戦術
- 評判
- 監督レベル
- 通算試合、勝、分、敗
- 昇格、優勝、カップ制覇
- 若手育成実績
- 財務評価
- 選手管理評価

評判はクラブ格、成績、目標達成、タイトル、解任、メディア評価で変動する。

## 2.2 スタッフ市場

スタッフ種別:

- ヘッドコーチ
- 攻撃コーチ
- 守備コーチ
- GKコーチ
- フィジカルコーチ
- 医療責任者
- スカウト
- ユース責任者
- 秘書

共通属性:

- 能力値
- 年齢
- 給与
- 契約残期間
- 性格
- 評判
- 得意分野

効果:

- コーチ: 成長、戦術習熟、自動編成
- フィジカル: 体力回復、疲労耐性
- 医療: 怪我予防、診断精度、復帰速度
- スカウト: 視察速度、精度、地域知識
- ユース: 候補数、潜在能力、性格
- 秘書: 提案精度、要対応の優先順位

スタッフ枠と給与総額を設ける。高能力スタッフを集めるほど維持費が増える。

## 2.3 選手性格とチーム内関係

選手へ以下を追加する。

- 性格特性
- 監督への信頼
- クラブへの忠誠
- 野心
- プロ意識
- プレッシャー耐性
- リーダーシップ
- チーム内グループ

性格特性例:

- プロ意識が高い
- 野心家
- 忠誠心が高い
- 気分屋
- リーダー型
- 若手の面倒見がよい
- プレッシャーに弱い

チーム内グループは最大4つ。主将、古参、同年代、同地域などから形成される。不満や約束違反が同グループへ波及する場合がある。

## 2.4 選手面談と約束

面談種別:

- 出場機会
- 契約更新
- ポジション変更
- キャプテン任命
- 移籍希望への対応
- 活躍を褒める
- 不調を注意する
- 休養を与える

約束は期限、条件、進捗、成否を持つ。

例:

- 今後5試合中3試合で先発
- 8週以内に契約更新交渉
- 次の3試合は指定ポジションで起用
- 今季終了まで売却しない

約束達成で信頼、士気、契約意欲が上がる。違反で信頼低下、不満、移籍希望、グループ反発が発生する。

## 2.5 理事会とサポーター評価

評価軸:

- リーグ成績
- カップ戦
- 財務
- 若手起用
- 攻撃的内容
- 地元選手起用
- スター維持
- サポーター人気

クラブ方針ごとに重みを変更する。

シーズン開始時に以下から目標を選ぶ。

- 安全
- 標準
- 挑戦

難易度が高いほど予算、評判、達成報酬が増える。評価が低下すると警告、最終通告、解任へ進む。

## 2.6 監督市場

イベント:

- 他クラブからの打診
- 面接招待
- 正式オファー
- 契約延長
- 解任
- 無所属期間
- 再就職

クラブ移籍時は監督記録を維持し、クラブ状態だけを切り替える。オリジナルクラブから離れる場合もクラブはAI運営を継続する。

# 3. 第4弾: スカウト、移籍交渉、代理人

## 3.1 地域別スカウト網

地域:

- 北海道・東北
- 関東
- 中部
- 関西
- 中国・四国
- 九州・沖縄

スカウト担当を地域へ配置し、知識値を蓄積する。

未視察選手は以下を範囲表示する。

- OVR
- POT
- 市場価値
- 給与要求
- 性格
- 怪我リスク

視察回数とスカウト能力で範囲が狭まる。

## 3.2 移籍候補リスト

候補リストに以下を持つ。

- 優先度
- 必要ポジション
- 推定価格
- 視察進捗
- 競合クラブ
- 代理人態度
- 推奨理由

秘書とスカウトは、戦力不足、年齢構成、契約満了を見て候補を提案する。

## 3.3 クラブ間交渉

提示項目:

- 即時移籍金
- 分割払い
- 出場数ボーナス
- 昇格ボーナス
- 優勝ボーナス
- 売却益割合
- 買戻し条項
- レンタル料
- 買取オプション

複雑化を避けるため、同時に使える追加条項は最大3件とする。

AIクラブは財務、選手重要度、契約残期間、代替候補、競合状況を評価して返答する。

## 3.4 選手・代理人交渉

提示項目:

- 給与
- 契約年数
- 契約金
- 出場給
- 得点・無失点ボーナス
- 役割
- 契約解除金

代理人は性格を持ち、要求、期限、再交渉可能回数が変わる。他クラブとの競合がある場合は回答期限が短くなる。

## 3.5 レンタルと契約満了

- レンタル
- 給与負担割合
- 出場時間の約束
- 買取オプション
- 契約満了6か月前の事前交渉
- 自由契約選手

レンタル先での出場時間と成長を記録する。

# 4. 第5弾: 試合文化と環境

## 4.1 セットプレー設計

対象:

- 攻撃CK
- 守備CK
- 攻撃FK
- 守備FK
- ロングスロー

設定項目:

- キッカー
- 第1・第2ターゲット
- ニア、中央、ファー
- ショート選択
- こぼれ球担当
- カウンター残留人数
- マーク方式

完全自由配置ではなく、テンプレートと役割選択方式にする。

テンプレート例:

- ニア集中
- ファー狙い
- 中央密集
- ショートCK
- カウンター警戒

セットプレー習熟度を持ち、練習配分とスタッフ能力で上昇する。

## 4.2 天候とピッチ

天候:

- 晴れ
- 曇り
- 雨
- 強雨
- 強風
- 猛暑
- 寒冷

ピッチ:

- 良好
- 乾燥
- 重い
- 荒れている

影響:

- パス精度
- シュート精度
- 疲労
- 怪我率
- クロス
- ロングボール
- セットプレー

影響は最大でも試合能力の±8%程度に抑え、戦術選択の意味を作りつつ運要素を過剰にしない。

## 4.3 遠征疲労とホームアドバンテージ

クラブ所在地から移動距離を算出し、遠征疲労へ反映する。連続アウェイ、短い休養、気候差で増加する。

ホームアドバンテージはサポーター熱量、スタジアム規模、ダービー、直近成績で変化する。

## 4.4 ライバルとダービー

各クラブに0～3件のライバル関係を持たせる。

ダービーでは以下が変化する。

- 観客収入
- 士気
- プレッシャー
- カード率
- サポーター評価
- 監督評価

オリジナルクラブは同地域クラブとの対戦回数や重要試合からライバル関係が形成される。

## 4.5 審判傾向

審判属性:

- ファウル基準
- カード傾向
- アドバンテージ傾向
- ホーム圧力耐性

試合前レポートで傾向を表示し、プレス強度やタックル方針の判断材料にする。

# 5. 週間ゲームループ

1. ホームで要対応を確認
2. スタッフ提案、選手面談、約束へ対応
3. 次戦の天候、審判、相手、遠征情報を確認
4. スカッド、戦術、セットプレーを準備
5. スカウト、移籍、契約、スタッフ交渉を処理
6. 試合を実行
7. 理事会、サポーター、選手、監督評価を更新
8. 次週へ進む

自動進行は、以下で停止する。

- 選手の重要面談
- 約束期限
- スタッフ契約
- 移籍交渉期限
- 理事会警告
- 監督オファー
- ダービー、決勝、昇降格決定戦
- 重傷、退場、処理不能な試合状態

# 7. エラー処理

- 不正な交渉条件は状態を変更せずエラーを返す。
- 契約・約束・面談は一意IDを持ち、二重確定を拒否する。
- クラブ移籍時は現在進行中の試合、交渉、モーダルを先に閉じる。
- AI処理失敗時は安全な既定行動へフォールバックし、進行不能にしない。
- セーブ読込時に新規状態を検証し、破損データは読み込まない。

# 8. テスト方針

## 単体テスト

- スタッフ効果
- 面談と約束
- 信頼、不満、グループ波及
- 理事会・サポーター評価
- 監督評判とオファー
- スカウト精度
- 移籍・代理人交渉
- レンタル
- セットプレー効果
- 天候、遠征、審判、ライバル

## 統合テスト

- 1シーズンを通したスタッフ契約と評価
- 約束達成・違反
- 他クラブへの監督移籍後の継続
- スカウトから獲得まで
- AIクラブの交渉と補強
- 天候とセットプレーを含む試合
- ダービー後の反応
- 3シーズン連続進行

## UIテスト

- PC3カラム
- サイドバー折り畳み
- 右状況パネル
- スマホ5操作
- ボトムシート
- モーダルとフォーカス
- 横スクロール・はみ出し禁止
- 標準ダイアログ禁止

## 完了条件

- 既存81テストを維持
- 新規機能の自動テストを追加
- `npm run verify`成功
- `npm run build`成功
- PC 1366×768、1920×1080で主要操作が一画面内に収まる
- スマホ 360×800、390×844で横方向のはみ出しがない
- 3シーズン連続シミュレーション成功
- セーブサイズがブラウザ保存上限へ急増しない

# 10. リリース戦略

一つの大型PRへまとめるが、内部コミットは機能群ごとに分ける。各段階でテストを通し、最終的にsquashマージする。

実装中にスコープが過大と判明した場合も、設計対象は維持し、未完成機能を画面だけ追加することはしない。完成した機能群だけを有効化し、残りは同じブランチ上で完了させてからマージする。
