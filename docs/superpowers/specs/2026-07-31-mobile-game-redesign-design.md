# Football Director スマホゲーム全面刷新 設計書

作成日: 2026-07-31  
対象リポジトリ: `TI-06/football-director-sim`  
ステータス: ユーザー承認済み

## 1. 目的

既存のサッカー監督・クラブ経営シミュレーションのゲームロジックを活かしながら、スマホ向けWEBアプリとして画面構成、情報導線、キャラクター表現、試合演出、進行テンポ、ゲームバランスを全面刷新する。

今回の刷新では、既存UIへCSSや`MutationObserver`で装飾を後付けする方式を廃止し、新しい画面構成を正式なレンダリング層として実装する。

## 2. 確定事項

| 項目 | 決定 |
|---|---|
| 全体方針 | ホーム、試合、編成、移籍、経営を同じ優先度で刷新する |
| 画面遷移 | 現行遷移を維持せず、スマホ向けに再編する |
| 初期表示 | ホーム／ダッシュボード |
| セーブ互換 | 旧ローカル、旧JSON、旧クラウドセーブとは互換を持たない |
| 改修範囲 | 基本ルールを維持し、進行、情報整理、演出、バランスを改善する |
| 1シーズン | 5〜8時間を目安とする |
| 試合介入 | 基本自動、ハーフタイム・負傷・60分・75分など重要局面だけ介入 |
| 試合視点 | スマホ縦画面、上から見たフルコート |
| 選手表示 | 自チームは○、相手は●を基本とし背番号を常時表示する |
| 選手詳細 | 円をタップすると名前、体力、評価、警告などを表示する |
| 試合中の移動 | 常時動かさず、イベント発生時のみ関連選手が移動する |
| 下部ナビ | ホーム、試合、編成、移籍、メニューの5項目 |
| キャラクター | ミナ、ソータ、レイ、カズオの役割を維持し、最新デザイン基準で描き直す |

## 3. 非目標

- 実在選手、実在クラブ、実在リーグの導入
- 3D試合表現
- 22人分の常時スプライトアニメーション
- オンライン対戦
- 旧セーブデータの移行ツール
- ゲームルールをゼロから作り直すこと

## 4. 設計原則

1. **スマホを主対象にする**  
   320px〜430px幅で主要操作が成立し、横スクロールを発生させない。

2. **今やるべきことをホームへ集約する**  
   負傷、契約、交渉、理事会警告、次戦準備を複数画面へ分散させない。

3. **ゲームロジックと表示を分離する**  
   リーグ、試合計算、移籍、育成、財務などはDOMへ依存させない。

4. **軽量な試合表現を優先する**  
   画像アニメーションではなく、CSS円形要素と`transform`を使う。

5. **主要キャラクターは役割を明確にする**  
   キャラクターを装飾ではなく、各画面の案内役として使用する。

6. **操作を減らし、判断を残す**  
   確認クリックや待ち時間は減らすが、編成、戦術、移籍、経営の意思決定は残す。

## 5. 情報アーキテクチャ

### 5.1 スマホ下部ナビ

| ナビ | 役割 |

| 試合 | 次戦、日程、過去結果、試合センター |
| 編成 | フォーメーション、先発、控え、選手詳細 |
| 移籍 | スカウト、候補、交渉、契約 |
| メニュー | 戦術、育成、経営、記録、受信箱、保存 |

### 5.2 初期表示

ゲーム起動後、セーブデータがある場合はホームを表示する。新規開始時はキャリア作成完了後にホームへ遷移する。

### 5.3 メニュー配下

- 戦術・試合プラン
- ユース・育成
- クラブ経営
- 記録・タイトル
- 受信トレイ
- 秘書レポート
- セーブ、読込、リセット

## 6. 画面設計

## 6.1 ホーム

ホームは「次に何をするか」が一目で分かるダッシュボードにする。

### 上からの配置

1. クラブ名、シーズン、節、現在順位
2. ミナを配置したメインビジュアル
3. 次戦カード
4. 要対応カード
5. チーム状態サマリー
6. 最近の結果
7. 固定の主要アクション

### 表示内容

| 領域 | 内容 |
|---|---|
| 次戦 | 対戦相手、ホーム／アウェー、順位、直近成績、戦力差 |
| 要対応 | 負傷、不満、契約期限、交渉、理事会警告 |
| チーム状態 | 順位、予算、士気、平均体力、総合戦力 |
| 主要操作 | 試合開始、次の判断まで進行、次週へ進む |

同じ警告を複数カードへ重複表示しない。重要度順に最大5件を表示し、残りは一覧へ遷移する。

## 6.2 試合一覧・次戦

- 次戦を最上部へ表示する
- 日程と結果は時系列カードにする
- 重要試合にはダービー、昇格争い、残留争い、カップ戦のバッジを表示する
- 「試合開始」から試合センターを全画面表示する

## 6.3 試合センター

### 基本構成

1. 上部HUD
2. 縦長フルコート
3. 選択中選手パネル
4. 実況・イベントログ
5. 判断パネル

### 上部HUD

- 試合時間
- スコア
- チーム名
- 支配率
- シュート数
- 進行速度

### ピッチ表現

| 要素 | 表現 |
|---|---|
| 自チーム | 青系の○＋背番号 |
| 相手チーム | 赤系または黒系の●＋背番号 |
| GK | 太い外周で区別 |
| ボール | 小さい白丸 |
| ボール保持者 | 外側の光輪 |
| 疲労 | 透明度を下げる |
| 警告 | 黄色の小バッジ |
| 負傷 | 赤色の小バッジ |
| 交代 | 短いフェードアウト／イン |

### 動き

- 通常時は基本フォーメーション位置を維持する
- パス時は保持者、受け手、近隣選手だけ移動する
- ドリブル時は保持者とサポート選手が前進する
- シュート時は攻撃側と守備側の関係選手だけゴール周辺へ移動する
- カウンター時は関係する複数選手を大きく移動する
- セットプレー時は専用配置に切り替える
- イベント終了後は基本陣形へ戻す

試合計算の結果を表示アニメーションが変更してはならない。表示は計算済みイベントを視覚化するだけとする。

### 選手タップ

タップ時に次を下部パネルへ表示する。

- 選手名
- ポジション
- 背番号
- 体力
- 評価点
- 警告・負傷状態
- シュート、パス成功、タックルなど主要成績

### 介入タイミング

- ハーフタイム
- 負傷
- 退場
- 60分前後
- 75分前後
- 特定の戦術判断イベント

操作しない場合は、ミナの提案または既存試合プランに基づいて自動判断する。

### 進行速度

- 標準
- 高速
- 次の判断まで
- 結果まで

## 6.4 編成

### 構成

1. ソータを配置した編成ヒーロー
2. フォーメーション選択
3. 縦型ピッチ
4. 控え選手
5. 選手一覧
6. 選手詳細ボトムシート

### ルール

- 既存のドラッグ配置を維持する
- スマホではタップ選択→配置先タップも利用可能にする
- 主将、PK、固定起用、交代可否を表示する
- 体力、負傷、出場停止、不満をカード上で識別できるようにする
- 主要選手には専用ポートレートを使用できるが、全選手へ画像を必須にしない

## 6.5 移籍

レイを案内役とする。

### タブ

- おすすめ
- 候補リスト
- 交渉中
- 放出
- スカウト地域

### 改善点

- 補強優先ポジションを上部へ表示する
- 候補カードに能力、年齢、移籍金、給与、適合度を集約する
- 交渉手順をクラブ間交渉と個人条件へ明確に分離する
- 同じ候補の情報を複数箇所へ重複表示しない

## 6.6 クラブ経営

カズオを案内役とする。

### 表示内容

- 現金
- 移籍予算
- 給与予算
- 理事会評価
- 施設状況
- 継続投資
- シーズン目標

経営判断はカード形式で表示し、効果、費用、完了時期、リスクを確認してから実行する。

## 6.7 キャラクター

| キャラクター | 役割 | 主な表示場所 |
|---|---|---|
| ミナ | 戦術アシスタント、秘書 | ホーム、試合判断、通知 |
| ソータ | エース選手 | 編成、選手イベント |
| レイ | スカウト | 移籍、候補提案 |
| カズオ | クラブディレクター | 経営、理事会、予算 |

4人は最新の青基調2Dデザインへ描き直す。画像は透過WebPまたは透過PNGとし、必要サイズ以上の画像を読み込まない。試合中の22人には使用しない。

## 8. データフロー

### 通常画面

1. `controller`が現在のゲーム状態と現在画面を保持する
2. 各画面セレクタが表示に必要なデータだけを整形する
3. 画面レンダラーがHTMLを生成する
4. ユーザー操作を`controller`がゲームアクションへ変換する
5. ゲームエンジンが新しい状態を返す
6. 新形式で保存し再描画する

### 試合画面

1. 試合エンジンが次のイベントを確定する
2. 試合表示モデルへイベント、関係選手、開始位置、終了位置を変換する
3. CSS `transform`で関連選手だけ移動する
4. アニメーション完了後に実況と統計を反映する
5. 判断局面なら停止し、そうでなければ次イベントへ進む

## 9. 新セーブ形式

旧形式とは互換を持たない。

### 方針

- 新しいローカルストレージキーを使用する
- 新しい`saveVersion`を必須とする
- 旧保存キーは削除せず読み込まない
- JSONインポート時は新形式以外を明確なエラーにする
- クラウド保存も新形式だけを対象にする
- 新規キャリア作成後に初回保存する

### エラー表示

旧形式のJSONを読み込んだ場合は、破損扱いにせず「旧バージョンのセーブデータはこの版では読み込めません」と表示する。

## 10. ゲームテンポとバランス

### テンポ目標

| 項目 | 目標 |
|---|---:|
| 通常試合 | 2〜4分 |
| 重要試合 | 4〜6分 |
| 通常週の判断 | 3〜8分 |
| 移籍期間 | 20〜40分 |
| 1シーズン | 5〜8時間 |

### 改善対象

- 自チームが継続的に勝ちすぎる状態
- 成長速度と衰退速度
- 移籍予算と給与予算の循環
- 若手起用の利益とリスク
- 疲労、怪我、固定起用による負担
- 上位リーグ昇格後の難易度

調整はシード付き自動シミュレーションで複数シーズンを実行し、優勝率、昇格率、降格率、収支、平均勝点を比較して決定する。

## 11. エラー処理

| ケース | 対応 |
|---|---|
| 保存容量不足 | 状態を破棄せず、保存失敗を通知する |
| 旧セーブ読込 | 互換対象外であることを明示する |
| 試合イベント表示失敗 | 試合結果を維持し、アニメーションを省略して続行する |
| 画像読込失敗 | キャラクター領域を非表示または簡易プレースホルダーにする |
| 不正な画面遷移 | ホームへ戻す |
| 試合進行中の二重操作 | 操作ボタンを一時無効化する |
| クラウド通信失敗 | ローカル状態を維持し、再試行可能にする |

## 12. パフォーマンス要件

- 初期表示に不要なキャラクター画像を先読みしない
- 試合中の選手はDOM要素22個とボールを基本とする
- 選手位置更新はイベント単位とし、常時物理演算を行わない
- 移動は`transform`と`opacity`を中心にする
- 非表示タブ、バックグラウンド、モーダル表示中は試合描画を停止する
- `prefers-reduced-motion`では移動時間を短縮または無効化する
- 320px幅で横スクロールを発生させない

## 13. アクセシビリティ

- タップ領域は原則44px以上
- 色だけで警告、負傷、選択状態を表現しない
- 試合選手の円には背番号とアクセシブルな名称を付ける
- モーダルとボトムシートはフォーカスを管理する
- 主要操作はキーボードでも実行できる
- 実況ログは必要以上に`aria-live`で読み上げない

## 14. テスト戦略

### 既存テスト

ゲームロジック、複数シーズン、移籍、財務、保存の既存テストを維持する。旧セーブ互換だけは対象外として新形式へ置き換える。

### 追加テスト

| 分類 | 内容 |
|---|---|
| 単体 | 画面用セレクタ、試合表示モデル、新セーブ検証 |
| 統合 | 新規開始→ホーム→編成→試合→移籍→保存 |
| 試合 | イベントと選手移動対象の対応、判断停止、自動判断 |
| レスポンシブ | 320、360、390、430pxおよびPC |
| アクセシビリティ | 下部ナビ、モーダル、選手タップ、フォーカス |
| 長期 | 複数シーズン自動進行とバランス統計 |
| 回帰 | 既存リーグ、昇降格、カップ、育成、移籍、財務 |

### 必須コマンド

```bash
npm test
npm run check
npm run smoke
npm run build
npm run test:responsive
```

PRは上記がすべて成功してからマージする。

## 15. 実装段階

この設計は一つの完成形を定義するが、実装は次の独立した段階に分ける。

1. 新UIシェル、5ナビ、新セーブ境界
2. ホーム、メニュー、共通コンポーネント
3. 編成、選手詳細、キャラクター統合
4. 試合一覧、縦型試合センター、軽量アニメーション
5. 移籍、経営、育成、記録の再編
6. 進行テンポとゲームバランス調整
7. 全体回帰、レスポンシブ監査、コードレビュー

各段階は動作する状態でコミットし、最終的に1本のPRとしてレビュー可能にする。
